# Cache Strategy Pattern

## Overview
Multi-tier caching strategy for NestJS APIs using in-memory cache, Redis, and React Query.

## Cache Tiers

```
┌─────────────────┐
│  CDN (Static)   │ ← CloudFront (HTML, CSS, JS, images)
└─────────────────┘
        ↓
┌─────────────────┐
│  React Query    │ ← Client-side cache (user-specific data)
└─────────────────┘
        ↓
┌─────────────────┐
│  API Gateway    │ ← Edge cache (public endpoints)
└─────────────────┘
        ↓
┌─────────────────┐
│  Redis Cache    │ ← Shared cache (sessions, rate limits, data)
└─────────────────┘
        ↓
┌─────────────────┐
│  Database       │ ← Source of truth
└─────────────────┘
```

## Backend: Redis Cache

```typescript
// apps/api/src/cache/cache.service.ts
import { Injectable } from '@nestjs/common';
import { Redis } from 'ioredis';
import { z } from '@repo/validation';

@Injectable()
export class CacheService {
  private redis = new Redis(process.env.REDIS_URL);

  async get<T>(key: string, schema: z.ZodSchema<T>): Promise<T | null> {
    const cached = await this.redis.get(key);
    if (!cached) return null;

    try {
      return schema.parse(JSON.parse(cached));
    } catch {
      await this.redis.del(key); // Invalid cache, delete
      return null;
    }
  }

  async set<T>(key: string, value: T, ttlSeconds: number): Promise<void> {
    await this.redis.setex(key, ttlSeconds, JSON.stringify(value));
  }

  async del(key: string): Promise<void> {
    await this.redis.del(key);
  }

  async invalidatePattern(pattern: string): Promise<void> {
    const keys = await this.redis.keys(pattern);
    if (keys.length > 0) {
      await this.redis.del(...keys);
    }
  }
}

// apps/api/src/users/users.service.ts
import { Injectable } from '@nestjs/common';
import { CacheService } from '../cache/cache.service';
import { UserSchema } from '@repo/validation';

@Injectable()
export class UsersService {
  constructor(
    private cache: CacheService,
    private prisma: PrismaService,
  ) {}

  async findById(id: string): Promise<User> {
    const cacheKey = `user:${id}`;

    // Try cache first
    const cached = await this.cache.get(cacheKey, UserSchema);
    if (cached) return cached;

    // Cache miss, fetch from DB
    const user = await this.prisma.user.findUniqueOrThrow({ where: { id } });

    // Store in cache (5 min TTL)
    await this.cache.set(cacheKey, user, 300);

    return user;
  }

  async update(id: string, data: UpdateUserDto): Promise<User> {
    const user = await this.prisma.user.update({ where: { id }, data });

    // Invalidate cache
    await this.cache.del(`user:${id}`);
    await this.cache.invalidatePattern(`user:${id}:*`); // Related caches

    return user;
  }
}
```

## Frontend: React Query (via orval-generated hooks)

**NEVER hand-write `useQuery`/`useMutation`.** Consume the generated hooks from
`apps/web/src/hooks/generated/` and tune caching through their query options.
Note the React Query v5 name is `gcTime` (v4's `cacheTime` was renamed).

```typescript
// Global defaults — apps/web/src/lib/query-client.ts
import { QueryClient } from '@tanstack/react-query';

export const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 60 * 1000, // 1 min — data considered fresh
      gcTime: 5 * 60 * 1000, // 5 min — inactive cache retained (v5: gcTime, NOT cacheTime)
      retry: 2,
      refetchOnWindowFocus: false,
    },
  },
});
```

```typescript
// Per-query overrides via the generated hook's `query` options.
// useGetUser is generated by orval from the OpenAPI spec.
import { useGetUser, getGetUserQueryKey } from '@/hooks/generated';

export function useUserProfile(id: string) {
  return useGetUser(id, {
    query: {
      staleTime: 5 * 60 * 1000, // profile changes rarely
      gcTime: 10 * 60 * 1000,
    },
  });
}
```

```typescript
// Cache invalidation after a generated mutation — use generated query keys.
import { useQueryClient } from '@tanstack/react-query';
import { useUpdateUser, getGetUserQueryKey, getListUsersQueryKey } from '@/hooks/generated';

export function useUpdateUserProfile() {
  const queryClient = useQueryClient();

  return useUpdateUser({
    mutation: {
      onSuccess: (updatedUser) => {
        queryClient.setQueryData(getGetUserQueryKey(updatedUser.id), updatedUser);
        queryClient.invalidateQueries({ queryKey: getListUsersQueryKey() });
      },
    },
  });
}
```

## Cache Invalidation Strategies

### 1. Time-Based (TTL)
```typescript
// Short TTL for frequently changing data
await cache.set('stock-price:AAPL', price, 30); // 30 seconds

// Long TTL for rarely changing data
await cache.set('country-list', countries, 86400); // 24 hours
```

### 2. Event-Based
```typescript
// Invalidate on EventBridge events
@EventPattern('user.updated')
async handleUserUpdated(event: UserUpdatedEvent) {
  await this.cache.invalidatePattern(`user:${event.userId}:*`);
}
```

### 3. Manual Invalidation
```typescript
// Admin action triggers cache clear
@Post('admin/cache/clear')
async clearCache(@Body() dto: ClearCacheDto) {
  await this.cache.invalidatePattern(dto.pattern);
}
```

## Cache Warming

```typescript
// Warm cache on application startup
@Injectable()
export class CacheWarmer implements OnApplicationBootstrap {
  async onApplicationBootstrap() {
    // Warm frequently accessed data
    const popularUsers = await this.prisma.user.findMany({ take: 100 });

    for (const user of popularUsers) {
      await this.cache.set(`user:${user.id}`, user, 600);
    }
  }
}
```

## Best Practices
1. **Cache Key Naming**: Use consistent pattern `resource:id:subresource`
2. **TTL Strategy**: Short TTL for mutable data, long for immutable
3. **Validate Cached Data**: Use Zod schemas to validate on retrieval
4. **Cache Stampede Prevention**: Use locking or probabilistic early expiration
5. **Monitor Hit Rate**: Track cache hit/miss ratio (CloudWatch metrics)
6. **Invalidation**: Prefer explicit invalidation over long TTLs

## Anti-Patterns
- ❌ Caching user-specific data in shared Redis (use sessions)
- ❌ No cache validation (corrupt data can persist)
- ❌ Infinite TTL (data never refreshes)
- ❌ Not invalidating on updates (stale data)
