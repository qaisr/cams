# Database Design

## Input
$ARGUMENTS (feature name — e.g. "cart items for shopping feature")

## Process

### 1. Read Context
- Read `@specs/functional-specifications.md`
- Check `packages/database/prisma/schema.prisma` (existing models)
- Check `packages/database/prisma/migrations/` (existing migrations)

### 2. Schema Design
Apply `@.claude/standards/database-standards.md`:
- All models: `id String @id @default(uuid())`, audit fields, soft delete
- NEVER use PostgreSQL native ENUM — use `String` with `@db.VarChar(n)`
- Add CHECK constraints for bounded values via `@@check`
- PII fields: comment `/// @pii encrypted` or `/// @pii hashed`
- TIMESTAMPTZ: use `DateTime @db.Timestamptz`
- Money: use `Decimal @db.Decimal(19,4)` — never Float

### 3. ER Diagram

> The ER diagram MUST follow the binding standard
> `@.claude/standards/mermaid-standards.md` (`accTitle`/`accDescr`, portable
> syntax, consistent theming). Match the Prisma schema exactly — PK/FK and
> cardinalities.

```mermaid
erDiagram
    RESOURCES {
        uuid id PK
        string name
        string status
        uuid tenant_id FK
        datetime created_at
        datetime deleted_at
    }
    TENANTS {
        uuid id PK
        string name
    }
    RESOURCES }o--|| TENANTS : "belongs to"
````

### 4. Prisma Schema Addition

```prisma
model {Entity} {
  id          String    @id @default(uuid()) @db.Uuid
  name        String    @db.VarChar(200)
  /// @pii encrypted
  email       String?   @db.VarChar(255)
  status      String    @default("ACTIVE") @db.VarChar(20)
  deletedAt   DateTime? @map("deleted_at") @db.Timestamptz
  createdAt   DateTime  @default(now()) @map("created_at") @db.Timestamptz
  updatedAt   DateTime  @updatedAt @map("updated_at") @db.Timestamptz
  createdBy   String    @map("created_by") @db.VarChar(100)
  updatedBy   String    @map("updated_by") @db.VarChar(100)

  @@map("{entities}")
  @@index([status], where: "deleted_at IS NULL") // map: "idx_{entities}_status"
}
```

### 5. Run Generation Pipeline

```bash
# After schema update:
pnpm --filter @repo/database generate   # Generates Prisma client + Zod schemas
tsx apps/api/src/openapi/generate-spec.ts
pnpm --filter @repo/web orval
```

### 6. Seed Data (prisma/seed.ts)

```typescript
// packages/database/prisma/seed.ts
// Deterministic IDs for test/local environments
const SEED_IDS = {
  {entity}1: '11111111-1111-1111-1111-111111111111',
  {entity}2: '22222222-2222-2222-2222-222222222222',
};

await prisma.{entity}.createMany({
  data: [
    { id: SEED_IDS.{entity}1, name: 'Fixture 1', status: 'ACTIVE', createdBy: 'seed', updatedBy: 'seed' },
    { id: SEED_IDS.{entity}2, name: 'Fixture 2', status: 'DRAFT', createdBy: 'seed', updatedBy: 'seed' },
  ],
  skipDuplicates: true,
});
```

### 7. Review Checklist

- [ ] ER diagram accurate
- [ ] All models have mandatory audit fields
- [ ] PII tagged in comments
- [ ] No PostgreSQL native ENUM (use VarChar + CHECK constraint)
- [ ] No Float for money (use Decimal)
- [ ] Indexes justified with comments
- [ ] Seed data uses deterministic UUIDs
- [ ] Generation pipeline runs cleanly
