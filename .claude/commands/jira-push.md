# /jira-push — Feature A (push local mirror edits)

## Input

`$ARGUMENTS` — `<mirror-file> | --spec <artifact>`

- `<mirror-file>` — a `jira/<type>/{KEY}.md` the human edited (default entry).
- `--spec <artifact>` — a spec/epic artifact (e.g. `specs/epics/epic-003-*.md`) as the diff source
  instead of a mirror file; same engine, different Step-1 source.

Requires `jira/.manifest.json`. If absent → tell the user to run `/jira-init` and STOP.

## What this writes (only after an explicit Apply)

| Path | When |
|---|---|
| `jira/<type>/{KEY}.md` + `.json` | Step 7 reconcile after a successful edit (via `/jira-add-issue` Step-4 gate) |
| `jira/.manifest.json` | item pointer refresh |
| `jira/_index.json` | regenerated by `/jira reindex` (derived) |
| `specs/<name>/jira-mapping.json` | only if the artifact traces to a spec |

**Never** writes `specs/` requirement docs. Remote write is **description-only**.

## Engine

This command is a thin **Feature-A entry** into the shared pipeline. Follow
`.claude/commands/jira-write-engine.md` for Steps 2–8 verbatim (dry-run → approve → re-check →
mutate → re-pull → reconcile → suggest). Only Step 1 and the A-specific guard are described here.

### Step 1 — DIFF (Feature-A source)

**Mirror-file mode (default):**
1. Read the edited `jira/<type>/{KEY}.md` and its sidecar `.json`.
2. `partitionRegions(md)` → split on the stable `##` anchors + `<!-- pushable -->` / `<!-- pull-only -->`
   markers. **Pushable = `## Description` + the in-description AC checklist**; everything else
   (`## Status`, `## Links`, `## Comments`, any unknown heading) is pull-only (fail-safe).
3. `newPushable = pushablePayload(regions)`. Compute the **push-diff key** `hashPushable(newBody)` and
   compare to the sidecar's stored pushable hash (recompute from `contentHash` body if not stored).
   - **Equal ⇒ empty pushable diff ⇒ no-op.** If the human also edited a pull-only region, list
     *exactly which of their edits will not travel* (they are pull-only), then STOP. This is the
     "pull-only reported-and-skipped" behaviour.
   - **Different ⇒** the change intent is `{ key: KEY, pushablePayload: newPushable,
     pull_only_edits: [<any pull-only region the human also touched>] }`.
4. Also recompute `localEditsHash = hashBody(mdBody(md))` for the Step-4/Step-7 version+hash logic.

**`--spec` mode:** Step 1 source is the spec/epic artifact. Extract the requirement/AC prose for the
target key(s), render it as the candidate `## Description` + AC checklist, and produce the identical
change intent. Everything downstream (Steps 2–8) is unchanged — this is why the shared engine is built
first.

### A-specific decomposition — "unit tests + a11y as ACs" (§8.3)

A request like *"add unit tests and accessibility as acceptance criteria"* is **not one op**. Before
Step 2, split it per clause and ask the human per item (`AskUserQuestion`):
- a plain requirement → goes into `## Description`;
- **accessibility** → an AC checklist bullet (stays in Feature A, description-only);
- **unit tests** → offer **both**: (a) an AC checklist bullet, **or** (b) a child testing **sub-task**
  — branch (b) leaves Feature A and enters **Feature B** (`/jira-create`) as a create under this key
  as parent.

Each accepted clause becomes its own change intent through the engine.

### Steps 2–8

Run exactly as defined in `jira-write-engine.md`:
- **Step 2 DRY-RUN:** per-change `description` old→new + added/removed AC bullets + the pull-only-skip
  list.
- **Step 3 APPROVE:** per change [Apply / Skip / Edit].
- **Step 4 RE-CHECK:** `getJiraIssue` current `version`; if advanced past sidecar ⇒ STOP + 3-way, no
  mutation (lost-update guard).
- **Step 5 MUTATE:** `editJiraIssue { fields: { description }, contentFormat: "markdown" }` +
  one `[CANS-SYNC|…|run=…]` audit comment.
- **Step 6 RE-PULL:** `getJiraIssue { fields:["*all"], expand:"renderedFields" }`.
- **Step 7 RECONCILE:** `convertItem` → write via `/jira-add-issue` Step-4 gate; sidecar
  `contentHash = localEditsHash`, bumped `version`, `status_sync: "clean"`; update manifest +
  `/jira reindex`.
- **Step 8 SUGGEST:** if the key sources a spec (per `specs/sources/manifest.json`, skip silently if
  absent), print a `/reconcile-requirements` suggestion — never auto-run.

## Guardrails

- **Description-only.** Status/Links/Comments never travel; they are reported-and-skipped.
- **Empty pushable diff = no-op** — no write, no duplicate `[CANS-SYNC]` comment (idempotency =
  dual-hash + version, not the comment).
- **Lost-update guard** — Step 4 STOPs on a remote version advance and shows a 3-way; never clobbers.
- **`mdBody()` before `hashBody()`** when recomputing `localEditsHash`, or a title rename reads as a
  false edit.
- **Never auto-run `/reconcile-requirements`** — Step 8 only suggests (R3). Never edits `specs/` docs.
- **No secrets** — MCP brokers auth; cloudId is the pinned `CONNECTION` value.
